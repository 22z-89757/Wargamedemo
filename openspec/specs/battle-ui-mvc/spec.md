# battle-ui-mvc Specification

## Purpose

为战斗场景提供分层且可独立刷新的 MVC 用户界面，使回合状态、选中单位、能力操作和提示信息能够从统一战斗状态渲染，同时保持纯展示内容不拦截棋盘交互。

## Requirements

### Requirement: 战斗 UI 使用统一状态驱动展示

战斗 UI SHALL 从统一的战斗状态读取回合、选中单位、AP、能力和目标预览；视图 SHALL 只渲染状态并发出用户意图，不能直接修改单位属性、回合状态或造成战斗效果。

#### Scenario: 战斗状态变化后视图同步
- **WHEN** 回合、选中单位、AP、能力可用性或目标预览发生变化
- **THEN** 相关视图在下一次刷新中显示最新状态，且不保留已失效的选择或操作状态

#### Scenario: 视图事件提交用户意图
- **WHEN** 用户点击目标、能力、开火或结束回合控件
- **THEN** UI 将意图交给战斗控制流程，由战斗系统执行校验和提交，视图本身不直接扣 AP 或修改战斗属性

### Requirement: 顶部独立显示回合信息

系统 SHALL 在屏幕中央正上方使用独立的 Text 组件分别显示当前回合数和当前行动方；回合数与行动方不得合并为同一个文本字段，并 SHALL 随回合状态变化刷新。

#### Scenario: 玩家回合显示
- **WHEN** 战斗进入第 2 轮且当前行动方为玩家
- **THEN** 顶部回合数文本显示“第 2 回合”，行动方文本显示“玩家回合”

#### Scenario: 阵营切换显示
- **WHEN** 当前行动方从玩家切换为敌人
- **THEN** 行动方文本更新为“敌人回合”，回合数文本保持当前轮数

### Requirement: 战斗界面文字使用中文

战斗 UI 面向玩家显示的标题、提示、按钮、目标信息、能力状态、命中率和射击结果 SHALL 使用简体中文；能力和战斗底层标识可以继续使用内部 ID，但不得直接作为面向玩家的英文文案。

#### Scenario: 移动与射击提示中文化
- **WHEN** 玩家处于待机、移动拖拽、目标选择或射击结果状态
- **THEN** 对应提示显示中文文案，且不出现现有英文提示词

#### Scenario: 能力状态中文化
- **WHEN** 右侧能力列表显示能力的可用状态或失败原因
- **THEN** 状态显示中文名称，例如可用、行动点不足、冷却中或非当前回合

### Requirement: 右侧显示选中玩家单位信息和能力操作

系统 SHALL 在屏幕右侧显示当前选中且可下达命令的玩家单位名称、当前 AP/最大 AP 和其全部已授予能力；每项能力 SHALL 显示中文名称、当前 AP 消耗及实时可用状态，并从能力系统读取状态而非复制判断规则。

#### Scenario: 选中单位后刷新信息
- **WHEN** 玩家选中一个存活的己方单位
- **THEN** 右侧面板显示该单位名称、AP/最大 AP 和全部已授予能力

#### Scenario: 切换单位清除旧信息
- **WHEN** 玩家切换到另一个己方单位或取消选择
- **THEN** 右侧面板立即替换为新单位信息，或显示无选中单位状态，不沿用旧单位能力按钮

#### Scenario: 能力状态随属性变化
- **WHEN** 选中单位的 AP、回合资格、冷却、次数或阻挡标记变化
- **THEN** 对应能力项更新可用状态和原因，且不会执行能力

#### Scenario: 点击能力控件提交激活意图
- **WHEN** 玩家点击一个当前可用的能力操作
- **THEN** 控制器向能力系统提交该能力及其目标意图；能力系统完成最终校验和 AP 扣除，点击本身不绕过校验

### Requirement: 只读与交互 UI 分属不同 Canvas

系统 SHALL 将不需要交互的回合信息、选中单位信息、提示和结果放在只读 Canvas，将目标列表、能力操作、开火、旋转、结束回合和确认控件放在交互 Canvas；只读 Canvas 不得通过 GraphicRaycaster 或 Graphic raycast 阻挡棋盘输入。

#### Scenario: 只读 UI 不阻挡棋盘
- **WHEN** 指针按下或拖动经过回合信息、能力状态文本或结果提示
- **THEN** 输入系统将其视为非 UI 阻挡区域，棋盘选择、移动或相机手势仍按原规则处理

#### Scenario: 交互控件阻挡棋盘
- **WHEN** 指针按下交互 Canvas 中的目标按钮、能力按钮、结束回合按钮或确认按钮
- **THEN** 输入系统将其识别为 UI 操作，棋盘手势不应同时提交

#### Scenario: Canvas 装配错误被拒绝
- **WHEN** 只读 Canvas 带有会拦截输入的 GraphicRaycaster 或其 Graphic 开启 raycast
- **THEN** 战斗 UI 初始化报告明确配置错误，不静默以错误分层运行

### Requirement: 未用 AP 时结束回合需要确认

当玩家请求结束回合时，系统 SHALL 检查当前玩家阵营全部存活单位的 AP；任一单位 AP 大于零时 SHALL 先显示中文确认提示，提供确认和取消两个选项，未确认前不得切换回合。

#### Scenario: 仍有未使用行动力
- **WHEN** 当前玩家回合中至少一个存活玩家单位 AP 大于零，且玩家点击结束回合
- **THEN** 显示“仍有行动力未使用，确定要结束回合吗？”之类的中文提示，回合保持不变

#### Scenario: 取消结束回合
- **WHEN** 玩家在未用 AP 提示中点击取消
- **THEN** 关闭提示，保持当前回合、单位 AP、选中单位和能力状态不变

#### Scenario: 确认结束回合
- **WHEN** 玩家在未用 AP 提示中点击确认，且结束回合条件仍有效
- **THEN** 关闭提示并只调用一次结束玩家回合流程，随后刷新回合信息、AP 和能力列表

#### Scenario: 所有存活玩家单位 AP 为零
- **WHEN** 当前玩家阵营所有存活单位 AP 均为零，且玩家点击结束回合
- **THEN** 不显示确认提示，直接执行一次结束玩家回合流程

#### Scenario: 确认期间状态失效
- **WHEN** 确认提示显示期间回合已切换、战斗结束或结束回合条件失效
- **THEN** 确认操作不重复结束回合，并刷新或关闭过期提示
