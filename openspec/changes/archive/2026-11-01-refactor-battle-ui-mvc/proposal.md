# 提案：战斗 UI MVC 重构

## Why

当前 `BattleHUD` 同时承担战斗状态读取、文字拼接、目标列表创建、按钮事件绑定和输入布局，状态展示与交互控制彼此耦合；场景中的英文标签也让玩家难以理解当前回合、行动点和可执行操作。现在需要把战斗状态转换、显示视图和用户操作入口拆开，使回合信息、选中单位信息、能力操作和目标选择能够独立刷新，并避免纯展示 UI 阻挡棋盘输入。

## What Changes

- 将战斗 UI 重构为 MVC 分层：由控制器接收按钮/列表事件并调用战斗系统，由模型或视图模型提供回合、选中单位、AP、能力和目标预览状态，视图只负责渲染序列化的 Text、Button、列表和提示。
- 在屏幕中央正上方增加独立的回合数 Text 与当前行动方 Text；两者独立存储并随 `BattleTurnManager` 状态刷新。
- 将现有战斗 UI 文案统一为简体中文，包括移动提示、目标列表、命中率、射击结果、回合按钮和确认提示。
- 在屏幕右侧增加当前选中玩家单位的信息面板，显示单位名称、当前/最大 AP，以及从 `AbilityComponent.Abilities` 读取的全部已授予能力；每项显示中文名称、AP 消耗和实时可用状态，交互由 UI 控制器转发给能力系统。
- 将现有 `BattleUICanvas` 拆分为只读信息 Canvas 与交互 Canvas：只读 Canvas 关闭 GraphicRaycaster 或阻止其 Graphic 的 raycast，不拦截棋盘操作；目标选择、能力操作、开火、结束回合和确认对话框保留在可交互 Canvas。
- 结束回合时检查当前玩家阵营全部存活单位是否仍有 AP；若有未使用 AP，先显示可确认或取消的中文提示，确认后才调用结束回合，取消则保持当前状态。
- 保留现有远程攻击目标合法性、命中率和开火结算规则；目标列表仍只选择目标，不直接消耗 AP 或造成伤害。
- 将依赖旧 `BattleHUD` 公共控件入口的非必要测试迁移到新的状态快照、MVC 控制器和分层视图测试；移除只验证旧 getter、旧按钮集合或旧渲染入口的测试，保留面向玩家行为的移动、目标选择、射击和回合回归。
- 增补 EditMode 与 PlayMode 验证，覆盖回合/选中状态刷新、能力列表、中文文案、Canvas 输入穿透、AP 确认流程及既有移动/射击回归。

## Capabilities

### New Capabilities

- `battle-ui-mvc`: 定义战斗 UI 的状态视图模型、回合与选中单位信息展示、能力操作列表、中文本地化、Canvas 输入分层及结束回合 AP 确认流程。

### Modified Capabilities

- `ranged-attack-targeting-ui`: 目标列表、命中率、开火按钮和射击结果改用中文，并明确归属于可交互 UI 层；目标选择仍由控制器驱动，不由视图直接执行战斗。

## Impact

- 主要影响 `BattleHUD`、`BattlePlayerController`、`BattleSceneManager`、`BattleTurnManager` 及 `Map1.unity` 的 UI 装配。
- 新增战斗 UI 模型/视图模型、只读信息视图、交互视图、能力列表项和结束回合确认视图；可能调整现有 `BattleUICanvas` 下的对象层级与序列化引用。
- 需要从 `AbilityComponent` 暴露稳定的能力状态读取入口或由 UI 模型封装读取，不能在视图中重复能力可用性判断。
- 现有测试中只为旧 `BattleHUD` 访问器服务的非必要接口可以随迁移移除；新的测试应通过 UI 状态、控制器事件和视图的用户可见结果验证行为，不把旧测试接口作为兼容契约。
- 不引入新的本地化包；本次中文文案直接由战斗 UI 的显示层提供，底层能力 ID、失败枚举和战斗 API 保持兼容。
- 保留独立的 `UnitHealthBarCanvas`，并确保新只读 Canvas 与血条 Canvas 都不阻挡棋盘输入。
