# Design

## Context

参见 `proposal.md` 的动机与范围。现有移动预览复用逻辑格路径；`BattleCameraRig` 手动驱动 CinemachineBrain 并管理战术相机平移、旋转；Map1 的 Brain 默认混合为 Cut。`BattlePlayerController` 收到目标选择和射击确认，`UnitShootVisualController` 驱动探头、发射、命中回调及归位；`ShootAbility` 在子弹到达回调中完成结果判定，控制器在能力结束后展示当前 HUD 结果文本。Cinemachine 3.1.7 已安装。

## Goals / Non-Goals

**Goals:**

- 将拖动预览几何与规则寻路数据解耦，只绘制当前位置到目标格中心的世界空间线段。
- 在不取代战术镜头手势控制的前提下，统一调度战术、敌方聚焦和玩家射击镜头，并可恢复上一个有效视图。
- 让镜头、探头射击动画、目标上方结果提示由稳定的射击阶段事件衔接。

**Non-Goals:**

- 不改变棋盘移动合法性、路径成本、AP、射击命中判定、伤害或单位占格逻辑。
- 不增加 Cinemachine 包依赖，不重做输入系统、战术镜头操控或全局 HUD。
- 射击目标选择/确认阶段允许玩家取消整个待执行射击；一旦成功确认并开始射击视觉流程，不允许中途取消、切换目标或改变战术镜头状态，射击阶段以完成或对象失效作为恢复边界。

## Decisions

1. **移动规则路径与预览线分开。** `BattleMovementPreview` 只接收并渲染起点与终点，不再把 `GridReachabilityResult` 的逐格 path 顶点传给线渲染器；`BattlePlayerController` 仍使用原可达性结果判定目标和提交移动。线段端点采用单位当前视觉世界位置及候选格中心，故视觉线长度自然为欧式距离。相比在逻辑路径上做简化，直接使用端点可确保无论路径转折如何都只呈现一条线。

2. **由战斗相机协调器管理镜头优先级，保留 BattleCameraRig 的战术职责。** 扩展/配套控制器接收“聚焦目标”“开始射击镜头”“结果展示结束/取消”等意图；`BattleCameraRig` 继续负责战术中心、旋转和平移，不承担单位镜头生命周期。目标视角从敌方 Unit 预制体登记的四个方向相机中按战术视角的离散朝向选择；这是把用户提出的“四种旋转”解释为四个棋盘主方向，而非四个攻击方向。战术视角旋转结束后，重新按当前方向选择目标镜头。

3. **为过渡明确配置 Cinemachine Blend。** 将 Brain 的 Default Blend 从 Cut 改为可见的 Ease In Out 混合，并为战术、敌人聚焦及玩家射击相机配置稳定且互斥的优先级。相机切换交由 Brain 插值；不通过直接设置输出 Camera Transform 制造第二套状态。正常射击结果展示结束后清除敌人聚焦意图并恢复战术相机，战术中心设为本次发射单位；取消或对象失效时恢复当前有效的战术视角。

4. **射击相机跟随视觉根节点并动态瞄准目标。** 玩家 Unit 预制体配置一台射击虚拟相机，Follow 目标绑定移动/探头所在的视觉根节点，而不是记录逻辑位置或射击开始时的位置快照；LookAt 指向当前目标的瞄准点。镜头摆位由预制体后肩偏移配置。探头时镜头随视觉根移动，归位时也随之移动。

5. **以相机混合完成和射击视觉/规则回调定义阶段时序。** 确认且成功提交后先切入攻击者镜头并等待 Cinemachine Brain 完成向射击相机的混合；到位后才启动探身、子弹飞行和命中/未命中结算。子弹到达后由现有回调应用结果，能力视觉完成后显示目标上方结果跳字。结果停留计时从跳字实际显示时开始，完整持续 2 秒，再清除敌人聚焦并平滑返回以本次攻击者为中心的战术视图。取消或对象失效时立即清理提示、协程/Tween 和相机引用，并走统一恢复流程。这样避免镜头尚未到位就播放动作，也不会把两秒等待并入命中判定或子弹飞行。

6. **结果跳字是世界空间提示，HUD 文本可保留为辅助信息。** 结果提示跟随目标视觉位置并面向相机，展示命中/擦伤/未命中及实际伤害；目标已死亡但对象仍存在时，提示可在其最后有效位置完成停留，若对象销毁则在销毁回调前捕获展示点。相较仅延长 HUD 文本，目标上方提示能满足“跳字”语义并与聚焦镜头对应。HUD 当前结果文本是否继续同步更新不改变游戏规则。

7. **校验预制体资源并保持显式装配。** 场景启动校验需验证玩家射击相机/跟随瞄准点、敌人四方向相机、CinemachineBrain Blend 与唯一战术相机引用齐备；错误明确指出缺少的预制体或方向配置，不通过运行时查找或默认相机静默回退。此做法延续现有显式 Inspector 引用模式，避免不同 Unit 资源表现不一致。

8. **在射击确认前提供明确取消入口。** “取消射击”控件只在射击目标选择/确认阶段出现，并复用移动取消控件的屏幕位置和尺寸；两种互斥操作按当前模式显示对应文案。点击后由控制器统一关闭确认与目标界面、清除待执行能力和目标预览，再清除相机聚焦目标以平滑恢复普通战术视野；不扣 AP，也不打断已开始的射击、伤害结算或结果展示。

## Risks / Trade-offs

- [敌人预制体四个方向相机的偏移可能遮挡棋盘或穿过障碍] → 在 Prefab 中按四个棋盘主方向配置一致的焦距/高度，使用视线与裁剪面检查并在场景中逐方向验收。
- [Cinemachine Brain ManualUpdate 与新增 Blend/相机优先级调度时序不一致] → 所有镜头意图在同一战斗相机协调器内更新，保持 Brain 单一手动更新入口，并验证过渡期间每帧输出。
- [目标死亡导致跳字锚点丢失] → 结算事件捕获世界坐标快照供跳字展示；镜头目标失效时立即恢复战术视角，不依赖已销毁 Transform。
- [视觉预览直线可能跨越障碍，看起来像可穿行路线] → 保留可达目标提示与非法目标隐藏规则，并在 UI/规格中只把线定义为距离视觉，不作为路径承诺。
- [延长镜头保持会阻塞下一步输入] → 只锁定与当前射击流程冲突的相机/射击操作；若项目现有回合状态允许其他命令，待实现时以战斗状态约束校验，确保不提前结束结果阶段。
- [移动取消与射击取消共用屏幕区域可能造成误操作] → 仅在对应交互模式显示各自文案和可点击状态；射击按钮只出现在确认前阶段，位置和尺寸保持与移动取消控件一致。

## Migration Plan

1. 先调整移动预览接口并验证既有路径合法性与 AP 测试不变。
2. 更新 Map1 的 Brain Blend 和战术镜头协调，先只接入目标聚焦相机。
3. 更新玩家/敌人 Unit Prefab 相机装配与启动校验，再接入射击阶段事件和世界空间结果提示。
4. 在 Unity 中逐方向检查目标聚焦与探头射击镜头，运行战斗 PlayMode 测试；若资源装配或过渡产生回归，可回退场景/Prefab 相机字段及协调器接线，代码规则路径不受影响。

## Open Questions

无。四个敌方视角按棋盘主方向解释；结果跳字按目标上方世界空间展示并从实际显示时开始计时；正常射击流程结束后由攻击者为中心恢复战术视角。
