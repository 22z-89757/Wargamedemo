# 设计：能力目标选择与确认执行

## Context

动机与范围见 proposal.md。现有 BattleHUD 已通过 Inspector 绑定静态 UI，但能力按钮直接挂在交互 Canvas 下且与目标行共用模板；目标面板随单位选择自动显示，射击由独立 FireButton 提交。BattlePlayerController 负责棋盘手势及射击候选，BattleUiController 生成只读快照。AbilityComponent.TryActivate 会立即校验并扣费，不能用于准备目标。

## Goals / Non-Goals

**Goals:** 在既有 MVC 中增加明确的待用能力会话及共享确认模式，让准备、预览、取消均无领域副作用，最终提交仍复用能力系统；静态节点在场景中可配置。

**Non-Goals:** 不扩展 Cell 目标解析，不改变 LOS、射击概率、AP、移动或血条规则，不建立第二套能力判断规则。

## Decisions

### 1. 控制器管理目标操作会话

BattlePlayerController 保存待用 ShootAbility、选中目标和确认待提交标志；BattleUiController 的快照显式携带目标面板可见状态，不再从选中单位推断。显式 Select 动作（含重复选中）重置会话；每帧渲染不等于选择动作。确认先消费待提交标志，再重新检查同一选中单位、回合、能力授予、目标合法性、行动状态，最后调用一次 TryActivate。这样同步事件或重复按钮回调不能重复结算。替代方案是按钮闭包保存领域状态，但会保留过期单位和目标，故不采用。

### 2. 目标预览与可进入选择分离

只为现有 ShootAbility 枚举 GetPreview 候选，保留合法的 0% 目标。能力准备检查由能力系统提供忽略尚未选定目标的只读检查，仍覆盖授予、回合、标签、冷却、次数与费用，不调用 TryActivate，也不把 InvalidTarget 一概视为可用。AP 不足禁用能力入口；已经打开的列表在 AP 变化时仍按视野合法性展示，但确认不可提交。None/Self 能力使用真实默认目标并即时激活。移动从 UI 能力列表排除，仍保留拖拽。

### 3. 一个静态确认面板，两种明确上下文

将预置弹窗配置为 ActionConfirmDialog，使用明确的 None/EndTurn/Ability 模式及共享确认/取消按钮，分别发出对应意图。结束回合沿用现有存活己方 AP 检查。能力确认取消只消费本次确认，保留待用能力与仍合法目标并返回列表；成功后清空会话并关闭列表；目标失效关闭过期确认并刷新列表；单位、能力或回合失效清空会话。替代方案是另建射击弹窗，会重复结构与输入遮挡逻辑，故复用。

### 4. 弹窗输入按模式处理

两种确认模式均冻结移动、平移、边缘滚动和其它执行按钮。结束回合模式也冻结单位选择。能力确认模式允许棋盘上选择己方单位（含原单位），这次按下仅重新选择、关闭旧操作，不能启动或提交移动；随后新的手势恢复原规则。

### 5. Inspector 预置层级

小写 canvas 根下继续保持信息、交互、血条三个 Canvas。交互 Canvas 预置 AbilityDic（带布局组件）及独立 AbilityButtonTemplate；只对条目实例化，不创建父物体、弹窗、按钮模板或布局。目标面板仅保留行模板、列表与空提示，删除 FireButton 及事件/API。共享弹窗文本、确认/取消和引用全部序列化。信息层继续不阻挡射线。

## Risks / Trade-offs

- 确认前 AP、LOS、死亡或能力撤销 → 通过变化事件刷新并在确认入口再次验证，不信任旧预览。
- 重选同一单位被引用相等优化忽略 → 在输入控制器显式选择入口清理，而非依赖快照 SetSelected。
- 取消弹窗后残留回调 → 用模式和一次性待提交标志消费确认，禁用期间不响应旧按钮。
- 旧测试依赖自动列表/独立开火 → 迁移到能力点击、目标行、确认流程，保留领域射击及移动回归。
- 主规格 Purpose 仍提独立开火 → 后续规格同步时同步更新说明，本轮只维护当前变更的 delta 与实现文档。

## Migration Plan

先实现只读准备校验、会话与快照，再调整 HUD 和 Map1 场景引用，移除旧开火接口并迁移测试和 README。执行 OpenSpec 严格验证及 Unity EditMode/PlayMode 验证；只在取得结果后标记验收任务完成。回退时将本次代码、场景和测试作为同一组回退，避免留下缺失序列化引用。
