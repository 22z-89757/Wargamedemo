# 提案：能力目标选择与确认执行

## Why

当前能力按钮只对少数能力有专门分支，射击目标选择、独立开火按钮和能力激活分散在不同流程中，导致玩家无法用一致步骤完成有目标的能力。本次把能力按钮作为使用入口，把目标选择和执行确认收敛为明确流程，并让单位切换及时清除旧操作状态。

## What Changes

- **预置交互 UI 面板**：在 `BattleInteractionCanvas` 下由场景预先配置 `AbilityDic` 根物体，并由 `BattleHUD` 通过 Inspector 引用。能力按钮仍可按当前单位已授予能力动态生成，但只能作为 `AbilityDic` 的子物体；复用场景中的能力按钮模板，不在运行时创建父节点。能力列表排除 `MoveAbility`，移动仍使用既有棋盘拖拽流程。
- **调整能力按钮语义**：点击能力按钮即表示请求使用该能力。无目标能力和自身目标能力在控制器重新验证当前行动状态与 `CanActivate` 后立即调用能力系统；验证失败时不扣 AP、不产生效果并刷新可用状态或原因。按钮可用状态来自实时能力数据，最终提交仍以能力系统验证为准。
- **将目标面板改为按需显示**：左侧目标列表默认隐藏，仅当玩家点击一个需要 Unit 目标的可用能力后显示。列表只呈现该能力提供的合法候选目标和预览，并由目标行点击控件选择目标；目标行点击不激活能力、不扣 AP、不造成效果。保留目标行点击选择所必需的 Button，移除独立 `FireButton`、`FireRequested` 及列表外的开火提交逻辑。本次目标候选只覆盖现有 `ShootAbility` 的 Unit 目标，不扩展 Cell 目标能力，也不改变射程、LOS、命中率和伤害规则。
- **预置并复用确认窗口**：在交互 Canvas 中保留一个场景预置的共用确认窗口及确认/取消按钮，支持“结束回合”和“使用能力”两种上下文。Unit 目标能力选中目标后显示目标/能力确认内容；确认时重新验证玩家回合、单位选择、能力授予、目标合法性和能力可用性，再且仅再调用一次 `TryActivate`。取消只清除本次待提交状态并返回目标选择状态，不激活能力。结束回合仍沿用既有 AP 未使用确认行为。
- **定义切换单位时的清理规则**：切换到另一个玩家单位、取消选择，或再次点击当前已选中的玩家单位，都视为一次选择动作。该动作必须立即取消待用能力和目标、关闭目标面板与能力确认窗口，然后按当前单位重建能力按钮并刷新 AP/可用状态；不得沿用上一单位的目标或延迟确认。
- **保留结果展示与其它战斗行为**：射击成功/失败结果继续在只读信息层显示中文；回合、Canvas 输入分层、单位移动、旋转、结束回合 AP 检查及血条行为保持原规则。
- **测试迁移**：将依赖 `FireButton`、`FireRequested` 的断言改为能力点击→目标选择→确认/取消的用户流程测试；覆盖无目标能力即时提交、目标能力确认、取消无副作用、目标/行动条件在确认时失效、单位切换（含重复选中）清理状态、动态按钮归属 `AbilityDic`、移动能力不显示，以及目标列表仅在需要 Unit 目标能力激活流程中出现。

### 面板与场景对象清单

| 位置 | 预置对象/面板 | 用途与可见规则 |
| --- | --- | --- |
| `BattleInteractionCanvas` 右侧 | `AbilityDic` | 场景中预先创建的能力按钮容器；每个选中玩家单位显示除移动能力外的已授予能力，动态按钮作为其子物体生成和回收。 |
| `BattleInteractionCanvas` 左侧 | `TargetPanel` / `TargetList` | 场景中预置的目标面板、目标行模板和空目标提示；默认隐藏，只有选中需要 Unit 目标的能力后显示。每行按钮只选择候选目标并呈现预览。 |
| `BattleInteractionCanvas` 顶层 | `ActionConfirmDialog` | 场景中预置的共享确认窗口，包含提示文本、确认和取消按钮；按“结束回合”或“使用能力”上下文显示，不运行时创建窗口或按钮。 |
| `BattleInfoCanvas` | 射击/能力结果文本 | 只读显示最后结果，不接收输入，不负责提交能力。 |

### 交互时序

1. 初始化或玩家选择动作后，刷新选中单位 AP 与 `AbilityDic`；移动能力不加入能力按钮列表，目标面板和确认窗口关闭。
2. 点击无目标或自身目标能力时，立即重新检查当前单位、回合和能力状态，通过后调用 `TryActivate`；不经过目标面板或确认窗口。
3. 点击 Unit 目标能力时，记录待用能力、清除旧目标并显示该能力当前合法的 Unit 候选。若无合法候选，显示中文空状态且不提交能力。
4. 点击目标行只记录当前目标并显示其预览，然后打开能力确认窗口；此时不扣 AP、不调用能力效果。
5. 确认时重新检查同一玩家单位仍被选中、能力仍已授予、战斗仍允许下令、目标仍合法且能力仍可用。全部通过则关闭弹窗并调用一次 `TryActivate`；失败则不提交，关闭过期确认并刷新候选/状态。
6. 取消能力确认时不调用能力、不扣 AP，关闭确认窗口并返回目标列表，保留仍合法的当前目标供玩家改选或再次确认。
7. 在能力待选目标或确认期间发生玩家单位选择动作（包括重复点击当前单位），立即丢弃待用能力和目标并关闭两处交互面板；若确认窗口属于结束回合流程，则单位选择输入被冻结，不与弹窗同时处理。
8. 结束回合确认继续检查当前玩家阵营存活单位 AP；共享窗口关闭或确认后按原规则重新验证并最多轮转一次。

## Capabilities

### New Capabilities

无。本次扩展既有战斗 UI 能力与远程攻击目标选择行为。

### Modified Capabilities

- `battle-ui-mvc`：能力列表不显示移动能力；按钮点击执行无目标/自身能力，Unit 目标能力进入选择和共用确认流程；玩家选择动作清除待执行状态。
- `ranged-attack-targeting-ui`：左侧目标列表按需显示并只负责选择目标；移除独立开火按钮，选择目标后经共用确认流程执行射击。

## Impact

- 场景：`Assets/Scenes/Map1.unity`，在 `BattleInteractionCanvas` 下预置 `AbilityDic`，复核目标列表和共用确认窗口的 Inspector 引用及 Canvas 输入遮挡。
- UI：`BattleHUD` 移除 FireButton 和直接开火事件，接入预置能力容器、按需目标面板和带上下文的共用确认窗口；静态面板、模板和按钮继续由 Inspector/场景序列化。
- 战斗控制：`BattlePlayerController` 维护待用能力/目标状态，在确认时重新验证并调用能力系统；单位选择动作统一清除该状态。射击仍通过 `ShootAbility` 的目标预览和 `AbilityComponent.TryActivate` 校验、结算。
- 测试：调整 `Assets/Tests/PlayMode/BattleFlowPlayModeTests.cs` 的射击与确认流程断言，并增加 EditMode/PlayMode 覆盖能力目标阶段、状态清理、组件装配和无副作用取消。
- 不修改通用 `AbilityBase` 的目标规则，不增加 Cell 目标能力的候选枚举，不改变移动拖拽、射击概率、LOS、AP 费用或回合轮转规则。
