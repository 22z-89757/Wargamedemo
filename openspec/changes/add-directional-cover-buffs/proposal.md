# Proposal

## Why

地图已经保存格子四边的半掩体与全掩体信息，但单位运行时尚未获得对应状态，射击命中率也不会反映掩体保护。需要补齐方向性掩体 Buff、可配置命中修正与可解释的确认界面，让玩家能理解掩体为何改变命中率，并为以后增加更多命中率影响因素留下扩展空间。

## What Changes

- 在 Unit 对象上新增 `UnitCoverController`，监听单位占格与格子掩体变化，维护单位当前四个方向的掩体环境，并通过 `BuffComponent` 添加、替换或移除半掩体/全掩体 `CoverBuff`。
- 掩体只保护隔着对应边界射来的攻击；攻击者位于目标斜向时读取两个相邻方向，采用其中较高的掩体等级。
- 射击预览与最终提交统一应用掩体命中修正：半掩体默认降低 20 个百分点，全掩体默认降低 40 个百分点，两个值均由 `GameSettings` 配置并校验。
- 将命中率计算结果建模为结构化明细，包含基础命中率、具名修正项和最终钳制值；预览、确认与结算共享同一计算入口，避免 UI 自行计算或拼接业务字符串。
- 射击确认界面展示完整公式，例如“命中率 = 基础命中率 - 全掩体 40% = 30%”；目标列表及其他位置仍只展示最终命中率。
- 补充 EditMode 与 PlayMode 验证，覆盖移动后 Buff 切换、四向/斜向来袭、配置值、预览与结算一致性及不同 UI 场景的展示差异。

## Capabilities

### New Capabilities

- `unit-cover`: 定义单位如何根据当前格四边环境持续维护方向性半掩体/全掩体 Buff，以及环境变化时的更新行为。

### Modified Capabilities

- `ranged-attack`: 将方向性掩体修正、GameSettings 配置和可扩展的命中率计算明细纳入射击预览与结算契约。
- `ranged-attack-targeting-ui`: 在射击确认界面显示结构化命中率公式，同时保持目标列表等其他位置只显示最终值。

## Impact

- 影响 Unit/Buff 运行时组件、棋盘占格与格子变化监听、射击规则与 `ShootPreview`/`ShootResult` 数据结构。
- 扩展 `GameSettings`/`ShootSettings` 及其校验、快照和场景注入流程，并更新 `GameSettings.asset` 默认配置。
- 调整战斗 UI 状态适配与确认窗口渲染，但 UI 仍只消费能力提供的只读数据，不读取棋盘或重算命中率。
- Unit 预制体或场景 Unit 装配需要新增 `UnitCoverController`，相关初始化校验与自动化测试需要同步更新。
