# 提案

## 为什么需要

项目已经具备单位能力、行动点、属性、棋盘占格、死亡事件和独立 LOS 查询，但玩家目前只能移动，无法完成一次可操作的远程攻击。需要把这些现有系统串成一个最小闭环，同时把目标筛选、命中率预览和开火操作放在独立的战斗 UI 层，避免射击规则反向耦合输入、HUD 或场景物理。

## 变更内容

- 新增面向单位目标的射击能力，统一检查攻击者回合与存活状态、目标存活状态、敌我关系、棋盘登记、固定射程、LOS 和 AP。
- 新增首版固定射击结算：消耗 1 AP，基础伤害 4，基础命中率为 `clamp(Aim - Defense, 0, 100)`；命中后按目标 `Dodge` 概率转为擦伤，擦伤造成基础伤害的一半；最终伤害为 `max(0, 伤害 - Armor)`，扣减目标 `Health`。
- 新增可复用的攻击预览/结算边界，使 UI 只读取目标列表和预览数据，不直接访问属性公式或修改生命值。
- 在屏幕左侧增加可瞄准敌人列表：列表内容按当前选中的己方单位实时计算；切换不同己方单位时刷新对应列表；列表项可切换射击目标，并显示命中率信息。
- 只有存在有效选中目标且射击能力当前可激活时显示并启用“开火”按钮；点击按钮才提交 AP 并执行射击，失败时不扣 AP。
- 射击完成后刷新 UI；目标死亡继续通过现有 `Died`、棋盘占格清理和回合注销流程处理，并清理失效的目标选择。
- 不引入武器数据资产、弹药、动画、掩体命中修正、暴击、反击、AI、战争迷雾或复杂战斗表现。

## 能力范围

### 新增能力

- `ranged-attack`：定义单位射击的合法性、攻击预览、命中与伤害结算，以及与 AP、属性、LOS 和死亡流程的连接。
- `ranged-attack-targeting-ui`：定义按选中己方单位生成可瞄准敌人列表、目标切换、命中率展示和开火按钮的交互契约。

### 修改能力

- 无。现有 `grid-line-of-sight` 规格只作为射击合法性检查的依赖，不修改其要求。

## 影响范围

- 运行时代码：预计新增 `Assets/Scripts/Units/Abilities` 下的射击能力/攻击预览与结算类型，并扩展 `BattleSceneManager`、`BattlePlayerController`、`BattleHUD` 的连接点。
- UI：在现有 HUD 配置中增加目标列表项、命中率文本和开火按钮引用；列表刷新由战斗状态、选中单位、单位位置、属性、死亡和 LOS 变化触发。
- 测试：在 EditMode 覆盖射击条件、公式和 AP 原子性，在 PlayMode 覆盖目标列表、目标切换、开火按钮和死亡后清理。
- 依赖：复用 `AbilityComponent` 的激活/提交生命周期、`GridLineOfSightMap` 与 `GridLineOfSight`、`GridManager` 的占格查询、`BattleTurnManager` 的回合状态和现有 `Unit.Died` 清理链。
